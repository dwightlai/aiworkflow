# 分块问题与推荐策略清单

| 编号 | 问题 | 典型表现 | 推荐处理 |
|------|------|----------|----------|
| C01 | 上下文断裂 | 6步报销流程被切成3个chunk，用户问"第5步做什么"召回到的chunk不含步骤编号 | 以流程/步骤组为切分单元；保留步骤编号和序号；支持子chunk召回+父chunk回填完整流程 |
| C02 | 表格被截断 | 表头与数据行分离，单位、适用范围丢失，设备清单被切成多个碎片 | 表格按行组切分；每个表格chunk保留表名、表头行、单位列；大表按语义行组切 |
| C03 | QA配对打散 | 问题和答案分属两个chunk，搜索命中"分段长度"找到答案但找不到原问题 | 以QA对为原子单元切分；长答案二次切分但保留Q作为上下文前缀 |
| C04 | 代码块被截断 | JSON/代码块被按字符数硬切，请求体字段不完整，用户漏掉关键参数 | 代码块、JSON、YAML、SQL作为原子不可拆单元；超长按函数/类/对象边界切 |
| C05 | 标题内容分离 | "扫描分辨率不低于300dpi"这个内容脱离所属章节标题"一、扫描规范 > 1.1 分辨率要求" | 每个chunk附加section_path元数据；保留完整breadcrumb标题路径 |
| C06 | 步骤流程断裂 | 7步部署指南被切成3块，"设置系统参数"脱离了"第一步：基础环境准备"的上下文 | 按一级标题切分；步骤编号和步骤名始终在同一chunk；metadata记录前后步骤关联 |
| C07 | 长段落边界 | "合同最长不超过36个月"的原因（"每次续期12个月且最多续期2次"）落在下一个chunk | 先按句子切分再按语义合并；设置合理overlap；小块召回后回填父段落 |
| C08 | 条款引用缺上下文 | "第3个条件"跟"必须满足全部条件"分属不同chunk，3个条件的具体内容也在不同chunk | 条件列表整体保留；列表项用有序编号；chunk附加条件组完整信息 |
| C09 | 多主题混杂 | 会议纪要一个chunk包含4个议题，重排无法判断哪个议题最相关 | 按议题标题切分；每个chunk保留会议元数据（时间、参会人、议题名） |

## 推荐默认策略

### 第一阶段：文档解析

文档入库前先做结构化解析，识别并标记以下元素类型：
- 标题层级（H1-H6）
- 正文段落
- 表格（含表头、表体）
- 代码块（JSON / YAML / SQL / Shell / Python 等）
- 列表（有序/无序）
- 问答对
- 页眉页脚、页码

### 第二阶段：结构化分块

分块优先级从高到低：
1. **不可拆原子单元**：代码块、JSON 对象、完整表格 → 不切
2. **语义边界**：标题、段落、列表项边界 → 优先在此切
3. **QA 配对**：Q 和 A 必须在同一 chunk → 强行合并
4. **token 上限**：超过模型上下文上限时，按上述边界反向合并

**不要**只按固定字符数/token 数硬切。字符数是上限约束，不是切分依据。

### 第三阶段：元数据增强

每个 chunk 必须携带以下 metadata：
- `docTitle`：文档标题/制度名称
- `sectionPath`：breadcrumb 标题路径（如：采购制度 > 采购权限 > 软件订阅）
- `pageStart` / `pageEnd`：页码范围
- `chunkType`：段落/表格/代码块/FAQ/流程步骤
- `prevChunkId` / `nextChunkId`：前后关联
- `sourceRefId`：原始文件标识
- `parserVersion` / `chunkProfileVersion`：版本追溯

### 第四阶段：检索补偿

- 采用「子 chunk 召回 + 父 chunk 展示」策略：小块利于向量检索命中，大块利于 LLM 理解完整上下文
- 检索命中后自动向前后扩展 N 个相邻 chunk，补齐上下文
- 对表格/代码块等特殊类型 chunk 做二次检索（关键词 + 语义双路）

### 分块质量自查清单

上线前逐项验证：
- [ ] 一个完整的流程步骤是否在同一个 chunk 内？
- [ ] 表格行是否保留了表头？
- [ ] FAQ 的 Q 和 A 是否在同一 chunk？
- [ ] JSON / 代码块是否完整无截断？
- [ ] 每个 chunk 是否携带 sectionPath？
- [ ] 条件列表是否完整保留、有序编号？
- [ ] 会议纪要各议题是否独立成块？
- [ ] 长段落答案是否跨边界被切断？
- [ ] 是否能用问题集跑通 Recall@k 验证？
