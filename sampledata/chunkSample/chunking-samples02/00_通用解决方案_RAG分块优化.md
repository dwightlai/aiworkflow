# RAG 文档分块问题 — 通用解决方案

> 基于视频"企业生产级Agent知识库搭建"中提到的分块问题，整理六大典型场景及其解决方案。

---

## 一、六大分块问题的根因与解法

| # | 问题类型 | 根因 | 表现 | 推荐方案 |
|---|----------|------|------|----------|
| 1 | 上下文断裂 | 按固定字符数生硬切割 | 句子在中间断开、内容不完整 | 按句子/段落边界分割 + overlap |
| 2 | 表格截断 | 分割器不识别表格结构 | 表头与数据分离，数字失去含义 | Markdown 结构感知分块 |
| 3 | QA配对打散 | 问答对长度不均匀 | 问题与答案不在同一块 | 以 Q 标签为边界，按 QA 对整体切分 |
| 4 | 代码块截断 | 代码块被视为普通文本 | 对象/函数定义被拆散 | 代码块设为原子单位，不切分 |
| 5 | 标题内容分离 | 忽略标题层级关系 | 内容失去章节归属 | 保留标题路径，注入 breadcrumb 前缀 |
| 6 | 步骤流程断裂 | 操作步骤跨块 | 多数步骤在召回时丢失 | 自定义分块 + 相邻块关联 + 前后扩展 |


## 三、方案一：结构感知分块（推荐首选）

### 核心思路

不按固定长度切，而是**以标题层级、段落、列表项、代码块、表格为天然边界**。

### Markdown 文档分块流程

```
原始 Markdown
    ↓
1. 解析文档结构树（H1-H6 标题层级）
    ↓
2. 识别特殊区域（代码块、表格、列表、引用块）
    ↓
3. 以结构边界切分，每个标题+其内容作为一个分块单元
    ↓
4. 超长章节（> max_chunk_size）按子标题/段落进一步细分
    ↓
5. 短块（< min_chunk_size）与相邻兄弟块合并
    ↓
6. 每个块注入 breadcrumb 前缀（父级标题路径）
    ↓
7. 设置 10-15% 的上下文重叠
```

### 关键参数建议

| 参数 | 推荐值 | 说明 |
|------|--------|------|
| `max_chunk_size` | 800-1200 tokens | 中文约600-900字 |
| `min_chunk_size` | 150-250 tokens | 中文约100-200字 |
| `chunk_overlap` | 10%-15% | 字符重叠或结构重叠 |
| `原子块` | 代码/表格/公式 | 不切分，保持完整 |

## 四、方案二：语义分块（适合论文/白皮书）

### 核心思路

计算相邻句子的语义相似度，在**语义突变点**处切分。

### 流程

```
文本 → 分句 → 每句编码为向量
    → 计算相邻句之间的余弦相似度
    → 检测相似度显著下降的位置（语义边界）
    → 在边界处切分
```

### Python 示例（使用 bge-m3 模型）

```python
from sentence_transformers import SentenceTransformer
import numpy as np

model = SentenceTransformer("BAAI/bge-m3")

def semantic_chunk(text, window=3, threshold_sigma=0.8):
    """在语义突变点切分文本"""
    sentences = split_sentences(text)
    embeddings = model.encode(sentences, normalize_embeddings=True)
    
    # 计算每个位置的"新颖度"——与上下文的差异
    novelties = []
    for i in range(len(sentences)):
        # 与前面 window 句的平均语义对比
        ctx_start = max(0, i - window)
        ctx_mean = embeddings[ctx_start:i].mean(axis=0)
        novelty = 1 - np.dot(embeddings[i], ctx_mean)
        novelties.append(novelty)
    
    novelties = np.array(novelties)
    threshold = novelties.mean() + threshold_sigma * novelties.std()
    
    # 在 novelty 超过阈值处切分
    chunks = []
    buf = []
    for i, sent in enumerate(sentences):
        buf.append(sent)
        if novelties[i] > threshold and len("".join(buf)) > 300:
            chunks.append("".join(buf))
            buf = []
    if buf:
        chunks.append("".join(buf))
    
    return chunks
```

## 五、方案三：元数据增强（必须配合使用）

### Breadcrumb 前缀注入

每个分块在开头注入其所属的标题路径，确保召回后上下文可追溯。

```
块文本: "支持在管理后台的学员管理页面，点击批量导入..."
↓ 注入标题路径
增强后: "[云学堂 > 管理员指南 > 学员管理] 支持在管理后台的学员管理页面，点击批量导入..."
```

### 相邻块关联

为每个块记录前一块和后一块的 ID，召回时自动拉取邻居上下文。

```python
# 存储时
chunk = {
    "id": "chunk_042",
    "text": enhanced_text,
    "parent_title_path": ["报销指南", "日常费用报销"],
    "prev_chunk_id": "chunk_041",
    "next_chunk_id": "chunk_043",
    "chunk_type": "procedure_step"  # 标注块类型
}
```

## 六、方案四：检索补偿 — 小检索大上下文

### 核心思路

- **建立双层索引**：小块索引用于高精度检索，大块文本用于生成时的上下文
- **召回后扩展**：检索到小块后，自动向前后扩展 `N` 个句子或 `M` 个字符

### PowerRAG 策略（前置/后置扩展）

```
小块检索命中: chunk_042 = "第四步：选择审批人，默认为直属上级..."
    ↓ 自动扩展（取前后块或固定字符数）
扩展后上下文:
    chunk_041: "...第三步：上传发票电子版，系统支持PDF、JPG格式..."
    chunk_042: "第四步：选择审批人，默认为直属上级，如有特殊审批..."
    chunk_043: "第五步：点击提交按钮完成报销申请..."
```

## 七、场景 → 策略速查

| 文档类型 | 分块策略 | 参数 |
|----------|----------|------|
| Markdown 技术文档 | 结构感知分块 | max 800字，重叠 10% |
| FAQ / 问答集 | QA 对整体切分 | 以 "Q:" 或 "## " 为边界 |
| 法律/规范文件 | 结构感知 + 语义分块混合 | max 600字，breadcrumb 注入 |
| API 文档（含代码） | 结构感知 + 代码块原子化 | 代码块标记为不可切分 |
| 对话/客服记录 | 轮次分块 | 3-5 轮/块，重叠 1 轮 |
| 纯文本/无结构 | 递归字符分块（兜底） | max 600字，从大到小分隔符 |
| 表格报告 | 结构感知分块 | 表格整体作为一个块 |
| 长篇论文/白皮书 | 语义分块 | novelty > μ+0.8σ |

## 八、快速落地建议

### 如果你在用 FastGPT

FastGPT 商业版（深信服）已内置**自定义分块**功能，可以：

1. 将 Word/Markdown 文档转为 Markdown 格式
2. 按 `##` 标题自动分段（本质就是结构感知分块）
3. 手动调整分段边界
4. 设置分段重叠长度

**最佳实践**：先按标题自动分段 → 检查每段是否语义完整 → 手动微调边界。

### 如果你在自建 RAG

推荐直接使用 **LangChain 的 `MarkdownHeaderTextSplitter`**，它原生支持按 H1-H6 标题层级切分，自动保留标题路径。

## 九、分块质量自查清单

- [ ] 每个分块是否包含完整的一个语义单元（段落/小节/QA对）？
- [ ] 代码块和表格是否保持完整，没有被截断？
- [ ] 每个分块是否有足够上下文让 LLM 独立理解？
- [ ] 如果依赖上文（如"如上图所示"），上文是否在同一块中？
- [ ] 标题层级路径是否作为元数据保留？
- [ ] 相邻块之间是否有合理的重叠区（10-15%）？
- [ ] 块长分布是否均匀（避免大量过短或过长块）？
