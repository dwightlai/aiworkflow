# 完整 AI Studio 系统设计文档

## 1. 目标

把当前的技术底座升级为一个完整可用的 AI 工作流系统。第一轮不再停留在简单演示页，而是交付具备真实产品形态的 AI Studio：用户可以创建工作流、拖拽编排节点、配置 Prompt/LLM/条件分支、调试运行、发布版本、查看执行历史和节点日志。

产品结构采用“先 AI Studio，后平台治理”的路线。第一轮把 AI 工作流编排体验做完整；用户权限、租户、审计、监控等企业治理能力保留菜单和后端扩展点，后续阶段补齐。

## 2. 参考风格

整体后台框架参考 AIFLowy 风格：

- 左侧固定导航栏，按“AI 功能”和“系统管理”分组。
- 顶部为折叠菜单按钮、页面标题、面包屑。
- 内容区使用浅灰背景和白色卡片。
- 列表页采用搜索工具条、卡片网格、分页和卡片底部快捷操作。
- 系统管理菜单完整保留入口，即使第一轮只实现基础占位。

## 3. 信息架构

### 3.1 AI 功能

- 工作台：展示工作流数量、今日执行、成功率、模型调用等概览。
- 智能体 Bots：后续用于把工作流包装成可对话应用，第一轮保留入口。
- 工作流：第一轮核心模块。
- Prompt：管理 Prompt 模板，供 PROMPT 节点引用。
- 知识库：第一轮保留入口，后续实现文档上传、切分、向量检索。
- 工具插件：第一轮保留入口，后续实现 HTTP 工具注册和参数映射。
- 模型配置：第一轮实现基础模型供应商配置。
- 模型市场：第一轮保留入口。

### 3.2 系统管理

- 用户管理
- 角色管理
- 菜单管理
- 部门管理
- 数据字典
- 定时任务
- 日志管理

系统管理第一轮以页面框架和占位为主，不阻塞 AI Studio 主链路。

## 4. 核心页面

### 4.1 工作台

工作台是进入系统后的默认页面，展示：

- 工作流总数
- 今日执行次数
- 运行成功率
- 模型调用次数
- 最近运行失败列表
- 最近编辑的工作流

### 4.2 工作流列表

工作流列表采用 AIFLowy 卡片风格：

- 顶部搜索：名称、状态、更新时间。
- 第一个卡片为“创建工作流”。
- 每个工作流卡片展示名称、描述、状态、最近更新时间。
- 卡片底部提供：设置、运行、编辑、更多。
- 支持分页。

### 4.3 工作流设计器

设计器采用已确认的 A 布局：

- 顶部工具栏：返回、工作流名称、保存、发布、运行、版本。
- 左侧节点库：START、PROMPT、LLM、CONDITION、TEXT_TRANSFORM、END；KNOWLEDGE_RETRIEVAL 和 HTTP_TOOL 作为禁用/预告节点展示。
- 中间画布：使用 LogicFlow 或 X6 作为底层图编辑框架，支持拖拽节点、连线、选择、移动、删除、缩放、撤销重做。
- 右侧配置面板：根据选中节点类型切换配置表单。
- 底部调试台：输入 JSON、运行结果、节点日志、耗时、错误信息。

### 4.4 运行历史

运行历史页展示工作流运行记录：

- 工作流名称
- 版本
- 状态
- 开始时间
- 结束时间
- 耗时
- 错误摘要

支持按工作流、状态、时间范围筛选。

### 4.5 执行详情

执行详情页展示：

- 运行输入
- 最终输出
- 节点执行链路
- 每个节点的输入、输出、状态、错误、耗时
- 失败节点高亮

## 5. 第一版节点能力

### 5.1 START

定义工作流输入变量，并把用户运行输入写入执行上下文。

### 5.2 PROMPT

根据 Prompt 模板和上下文变量渲染文本。配置项包括：

- 模板内容
- 输入变量
- 输出字段名

### 5.3 LLM

调用模型供应商完成文本生成。配置项包括：

- 模型供应商
- 模型名称
- Prompt 来源
- temperature
- max tokens
- 输出字段名

第一轮可以先接入一个 OpenAI-compatible provider，并保留多供应商结构。

### 5.4 CONDITION

根据上下文字段进行条件判断。第一轮支持：

- 等于
- 不等于
- 包含
- 为空
- 不为空

### 5.5 TEXT_TRANSFORM

进行确定性文本处理。第一轮支持模板替换，例如 `Hello {{name}}`。

### 5.6 END

定义工作流最终输出字段。

## 6. 后端设计

### 6.1 模块

- `workflow-core`：工作流定义、版本、发布状态。
- `workflow-engine`：DAG 执行、上下文传递、节点执行记录。
- `ai-model`：模型供应商、模型配置、LLM 调用。
- `prompt`：Prompt 模板管理。
- `persistence`：PostgreSQL 持久化、Flyway 迁移。

### 6.2 持久化

当前内存存储升级为 PostgreSQL：

- workflow
- workflow_version
- workflow_run
- workflow_node_run
- prompt_template
- model_provider
- model_config

JSON 类型字段用于保存 DAG 定义、节点输入输出、运行上下文。

### 6.3 执行引擎

第一轮仍采用同步轻量 DAG 引擎：

- 从已发布版本读取 DAG。
- 从 START 节点开始执行。
- 按边和条件分支选择下游节点。
- 每个节点记录输入、输出、状态、错误、开始/结束时间。
- 节点失败时工作流失败。

并行分支、异步队列、失败重试、超时控制在后续阶段增强。

## 7. 前端技术方案

### 7.1 后台框架

使用 React + Ant Design，构建完整后台壳：

- 左侧菜单
- 顶部面包屑
- 路由布局
- 页面标题
- 卡片网格
- 表格和详情页

### 7.2 设计器

设计器继续保持可集成包结构：

- `workflow-schema`：共享 DAG 类型。
- `workflow-designer-core`：框架无关设计器核心，底层使用 LogicFlow 或 X6。
- `workflow-designer-react`：React 适配器。
- `workflow-designer-vue`：Vue 适配器。
- `workflow-designer-wc`：Web Component 适配器。

第一轮实现 React 管理端中的完整设计器体验，同时保持 core 不绑定 React。

## 9. 分阶段实施

### 阶段 1：后台壳和路由

实现 AIFLowy 风格后台框架、菜单、面包屑、工作台、系统管理占位页。

### 阶段 2：工作流列表和详情

实现工作流卡片列表、创建、编辑入口、发布状态、运行入口。

### 阶段 3：可视化设计器

引入 LogicFlow 或 X6，实现节点库、画布、连线、节点选择、右侧配置面板、保存草稿。

### 阶段 4：Prompt 和 LLM 节点

实现 Prompt 模板、模型配置、PROMPT 节点、LLM 节点和后端执行器。

### 阶段 5：调试台和执行历史

实现底部调试台、运行历史页、执行详情页、节点输入输出查看。

### 阶段 6：PostgreSQL 持久化

把工作流定义、版本、运行记录、节点记录从内存切换到 PostgreSQL。

## 10. 验收标准

第一版完整 AI Studio 通过以下标准：

- 用户可以在后台创建工作流。
- 用户可以在设计器拖拽节点、连线并配置节点。
- 用户可以保存草稿并发布版本。
- 用户可以配置 PROMPT 和 LLM 节点并运行。
- 用户可以查看运行输出、节点日志和失败原因。
- 刷新服务后数据仍保留在 PostgreSQL。
- 管理端具备完整左侧菜单和 AIFLowy 风格页面结构。
- 设计器包仍可被 React、Vue、Web Component 三种方式集成。
