> **用途**：面向公司领导、商务、售前——介绍 **AI Workflow 企业 AI 应用平台** 全貌  
> **建议时长**：25–35 分钟讲解 + 10 分钟 Q&A  
> **演示环境**：`http://localhost:18080`（admin / admin123）或开发环境 `8080`

## 一、开场（1 分钟）

**一句话：**

> **AI Workflow** 是企业级 **AI 应用编排与运营平台**——将大语言模型、企业知识库、可视化工作流、智能体与治理体系整合为统一底座，帮助组织 **低代码构建、规模化运营、合规落地** AI 应用。

**三句话价值：**

1. **让 AI 有用**：RAG 知识库 + 工作流编排，回答基于企业资料，支持编研与自动化  
2. **让 AI 可控**：多租户、组织权限、资产授权、全链路审计，满足政企治理要求  
3. **让 AI 可复用**：一套平台支撑问答、客服、编研、系统集成等多种场景，POC 成果可沉淀为资产

## 二、为什么现在需要（3 分钟）

### 2.1 行业背景

- 大模型能力已成熟，但 **「开一个聊天窗口」** 无法解决企业真实问题  
- 政企客户关注：**数据安全、权限可控、与现有系统融合、可持续运营**  
- 市场从「试用大模型」进入 **「建设 AI 基础设施、批量复制场景」** 阶段

### 2.2 企业落地 AI 的三类痛点

| 痛点 | 具体表现 | AI Workflow 如何应对 |
|------|----------|----------------------|
| **能力碎片化** | 模型接入、向量检索、Prompt、业务 API 分散在各项目 | 统一平台：模型 + 知识库 + 工作流 + 智能体 |
| **治理缺失** | 不知谁用了什么、数据是否越权、无法审计 | 租户隔离、资产授权、操作/运行双审计 |
| **交付周期长** | 每个场景从零开发，POC 难复制 | 可视化编排 + 模板 + 开放 API，资产可复用 |

### 2.3 市场定位

| | 通用大模型 SaaS | 单点 RAG 工具 | **AI Workflow** |
|--|----------------|---------------|-----------------|
| 定位 | 对话产品 | 文档问答 | **企业 AI 中台 / 应用工厂** |
| 流程编排 | ✗ | ✗ | **12 类节点 DAG 引擎** |
| 政企治理 | 弱 | 中 | **多租户 + 授权 + 审计** |
| 系统集成 | 弱 | 弱 | **Open API + 第三方应用白名单** |
| 私有化/信创 | 受限 | 不一 | **PostgreSQL + 达梦 + Ollama** |

**一句话定位：**

> 我们不是 ChatGPT 替代品，而是帮助企业 **「造 AI 应用、管 AI 资产、控 AI 风险」** 的基础设施。

## 三、平台是什么（5 分钟）

### 3.1 平台组成

```
                    ┌─────────────────────────────────────┐
  管理员 / 业务人员  │         AI Workflow 管理平台          │
                    ├──────────┬──────────┬───────────────┤
                    │ 工作流引擎 │ 知识库 RAG │  智能体 Bot    │
                    ├──────────┴──────────┴───────────────┤
                    │ 智能编研 │ 模型管理 │ Prompt 模板     │
                    ├─────────────────────────────────────┤
                    │ 租户与组织 │ 资产授权 │ 开放 API       │
                    └──────────────────┬──────────────────┘
                                       │
              第三方业务系统 ── Open API ──┤
                                       ▼
                          PostgreSQL / 达梦 · ES（可选）
```

### 3.2 功能模块一览

| 模块 | 能力摘要 | 业务价值 |
|------|----------|----------|
| **工作台** | 资产概览、最近执行、快捷入口 | 运营人员一屏掌握平台状态 |
| **工作流** | 可视化 DAG 设计、版本发布、运行监控 | 复杂 AI 流程低代码搭建 |
| **知识库** | 文档上传、智能分段、混合检索、命中测试 | 企业知识资产化、RAG 问答 |
| **智能体** | 对话入口，绑定工作流/模型/知识库 | 面向终端用户的 AI 应用 |
| **智能编研** | 模板 + 向导 + 工作流生成 + DOCX 导出 | 长文档、专题报告自动化 |
| **大模型** | 多 Provider、对话/嵌入/多模态、私有化 | 统一模型接入与切换 |
| **Prompt 模板** | 可复用提示词资产 | 标准化 LLM 调用 |
| **系统管理** | 租户、组织用户、第三方应用、审计日志 | 政企级治理 |

### 3.3 工作流引擎（差异化核心）

**12 类内置节点**，覆盖从输入到外部系统调用的完整链路：

| 类别 | 节点 |
|------|------|
| 流程控制 | 开始、结束、条件分支、循环 |
| AI 能力 | 大模型、Prompt 模板、知识库检索、问题分类 |
| 数据处理 | 文本处理、内容模板 |
| 系统集成 | HTTP 请求（调业务 API） |

**平台能力：**

- 拖拽设计、草稿/发布/归档版本管理  
- 模板变量 `{{ variable }}` 全节点通用  
- 节点级运行日志、耗时与失败诊断  
- 发布前 DAG 校验（无环、合法连线）

### 3.4 演示建议顺序（现场 12 分钟）

1. **工作台** — 平台整体感  
2. **大模型** — 多 Provider、私有化（Ollama）  
3. **知识库** — 上传文档 → 检索测试（RAG 核心）  
4. **工作流设计器** — 拖「检索 + 大模型」→ 调试运行  
5. **智能体** — 绑定工作流 → 多轮对话（最直观）  
6. **运行监控** — 执行记录、节点时间线（体现可观测）  
7. **（可选）智能编研** — 生成报告 + Word 下载  
8. **系统管理** — 租户 / 资产授权 / 第三方应用（体现治理）

## 四、典型应用场景（5 分钟）

### 场景 1：企业知识问答

- **用户**：全员、客服、业务查阅人员  
- **路径**：知识库 + RAG 工作流 + 智能体  
- **价值**：有据可查的问答，文档更新即刷新知识，统一答案口径  

### 场景 2：智能客服与意图分流

- **用户**：客服中心、热线、在线客服  
- **路径**：问题分类节点 → 条件分支 → FAQ 检索 / 工单 API / 人工  
- **价值**：提升首问解决率，降低人工压力  

### 场景 3：长文档与专题编研

- **用户**：档案编研、研报、政策汇编、专题写作  
- **路径**：编研模板 + 知识库 + 工作流生成 + DOCX  
- **价值**：数周初稿压缩到小时级，人员聚焦审校定稿  

### 场景 4：业务系统 AI 增强

- **用户**：ERP、OA、门户、行业业务系统用户  
- **路径**：HTTP 节点调业务 API + 开放 API 嵌入  
- **价值**：不重构老系统，在 API 层快速获得 AI 能力  

### 场景 5：集团多租户统一运营

- **用户**：集团总部 + 各子公司/单位  
- **路径**：租户隔离 + 组织用户 + 按单位/部门资产授权  
- **价值**：一次建设、多单位复用，总部统管模型与策略  

### 场景 6：私有化与信创环境

- **用户**：对数据出域敏感、需国产化栈的政企客户  
- **路径**：本地部署 + 达梦数据库 + Ollama 本地模型  
- **价值**：自主可控，满足安检与合规要求

## 五、企业级治理与安全（4 分钟）

> 领导/政企客户最关心的部分，建议单独强调。

### 5.1 多租户与组织体系

| 能力 | 说明 |
|------|------|
| **租户** | 独立数据边界；平台管理员可跨租户运维 |
| **组织架构** | 树形单位/部门；支持外部组织 ID 对接 |
| **用户与角色** | 平台管理员、单位管理员、应用用户、审计员等 |
| **登录会话** | JWT 认证，支持刷新与登出 |

### 5.2 资产授权

对 **智能体、知识库、工作流、大模型** 四类核心资产，按组织/部门配置 **USE / MANAGE** 权限，支持「本级 / 含下级」范围。

- 管理端：用户只能看到被授权的资产  
- 开放 API：应用白名单 ∩ 资产授权 ∩ 启用状态  

### 5.3 开放集成

| 组件 | 说明 |
|------|------|
| **第三方应用** | 注册应用、生成 API Key、配置资产白名单 |
| **开放 API** | `/api/open/**`，AppCode + ApiKey 认证 |
| **上下文 Header** | 透传用户/单位/部门，支撑审计与扩展 |
| **Java Client** | `aiworkflow-open-api-client`（Feign，已就绪） |
| **设计器 SDK** | 工作流设计器可嵌入第三方控制台 |

### 5.4 审计与合规

| 类型 | 内容 |
|------|------|
| **操作审计** | 登录、关键管理操作：用户、IP、事件、结果 |
| **运行审计** | 每次工作流执行：输入/输出、节点级日志 |
| **版本追溯** | 发布版本不可变，执行引用已发布快照 |
| **API 审计** | 开放 API 调用记录 App、User-Id、结果 |

### 5.5 安全关切速答

| 关切 | 平台能力 |
|------|----------|
| 数据在哪 | 私有化部署，客户自有数据库 |
| 模型外泄 | Provider 密钥服务端保管；可接 Ollama 本地模型 |
| 回答可信 | RAG 检索 + 引用片段；编研展示引用关系 |
| 国产化 | Java 17 + Spring Boot；**PostgreSQL / 达梦** |
| 接口标准 | OpenAPI 3.0 + Swagger UI |

## 六、技术架构（3 分钟，给技术型领导）

```
  管理员 / 业务用户              第三方业务系统
        │                              │
        ▼                              ▼
  ┌─────────────┐              Open API (AppCode+Key)
  │ Admin 控制台 │ ─── HTTPS ───────────────────────┐
  │ React + Vite │                                  │
  └─────────────┘                                  ▼
                                        ┌──────────────────┐
                                        │ aiworkflow-server │
                                        │ Spring Boot 3.3   │
                                        │ · 工作流引擎       │
                                        │ · 知识库 / Bot    │
                                        │ · 认证与授权       │
                                        └────────┬─────────┘
                                                 │
                                    PostgreSQL / 达梦 + Flyway
                                    Elasticsearch（可选，向量检索）
```

| 层级 | 选型 | 说明 |
|------|------|------|
| 后端 | Java 17 + Spring Boot 3.3 | 企业级生态，人才储备充足 |
| 前端 | React 18 + Ant Design 5 | 现代 SPA 管理控制台 |
| 数据库 | PostgreSQL / **达梦** | 信创适配 |
| 迁移 | Flyway | 版本化 Schema，升级可控 |
| 部署 | 单机 Jar / Docker / 可选 Nacos | POC 到生产灵活路径 |

## 七、部署与交付（3 分钟）

### 7.1 两种使用模式

| 模式 | 说明 | 适用 |
|------|------|------|
| **独立使用** | 完整管理控制台 + 组织用户 + 资产授权 | 企业/集团自建 AI 中台 |
| **能力嵌入** | 管理台或 Open API 对接现有业务系统 | OA、门户、行业系统增强 |

两种模式 **同一套产品**，按客户选择切换，无需两套代码。

### 7.2 标准交付物

| 交付物 | 说明 |
|--------|------|
| `aiworkflow-server.jar` | 平台后端 |
| 管理前端（静态资源） | 可独立部署或与后端同包 |
| 数据库迁移脚本 | Flyway，PostgreSQL / 达梦 |
| `aiworkflow-open-api-client` | Java 集成 SDK |
| OpenAPI 文档 | 标准接口规范 |
| 部署脚本 | standalone 一键启停 |

### 7.3 典型实施路径

| 阶段 | 周期 | 内容 | 成果 |
|------|------|------|------|
| **POC** | 1–2 周 | 部署 + 配模型 + 1 个知识库 + 1 个智能体 | 可演示问答 |
| **试点** | 2–4 周 | 工作流编排 + 权限 + 2–3 个场景 | 业务部门试用 |
| **推广** | 4–8 周 | 多租户/多单位 + 开放 API + 运维规范 | 规模化上线 |
| **深化** | 持续 | 编研、客服分流、业务 API 编排 | 场景复制 |

### 7.4 资源需求（参考）

| 资源 | 说明 |
|------|------|
| 应用服务器 | 1 台起（可按并发扩展） |
| 数据库 | PostgreSQL 或达梦 |
| GPU | 可选；也可调用云端/私有化 LLM API |
| 向量检索 | 小规模可用内置；大规模可选 Elasticsearch |
| 运维 | 0.5–1 人（模型配置、知识库维护、版本升级） |

## 八、竞争优势（商务话术）

**差异化三句话：**

1. **全栈而不单点**：不止 RAG，还有工作流、智能体、编研、治理  
2. **可运营而不只 POC**：版本管理、运行监控、审计、多租户  
3. **可集成而不封闭**：Open API + 白名单 + SDK，嵌入现有系统

**对比总结：**

> 买大模型 API = 只有发动机；买 RAG 工具 = 只有油箱；**AI Workflow = 整车 + 车队管理系统**。

## 十、领导 / 客户常见问题 Q&A

**Q1：和 ChatGPT / 文心 / DeepSeek 有什么区别？**  
A：大模型是能力来源之一；我们提供 **知识库、编排、智能体、权限、审计、集成** 全套企业落地能力。

**Q2：必须接云端大模型吗？**  
A：不必须。支持 OpenAI 兼容 API、DeepSeek 等，也可对接 **Ollama 本地模型**，数据可不出域。

**Q3：谁可以创建和管理 AI 应用？**  
A：平台管理员配租户与模型；单位管理员/业务人员在授权范围内创建知识库、工作流、智能体。

**Q4：怎么保证不同单位数据不串？**  
A：多租户隔离 + 组织级资产授权 + 运行审计，从数据和权限两层控制。

**Q5：能不能嵌入我们现有的 OA / 业务系统？**  
A：可以。提供标准 **Open API** 和 Java Client；也可 iframe 嵌入配置页或 SDK 嵌入设计器。

**Q6：POC 要多长时间？**  
A：标准环境 **1–2 周** 可完成「知识库 + 智能体问答」演示。

**Q7：信创 / 国产化要求能满足吗？**  
A：后端 Java/Spring Boot；数据库支持 **达梦**；可私有化全栈部署。

**Q8：上线后怎么运维？**  
A：平台内置运行监控、失败诊断、审计日志；知识库和模型可在管理台自助维护。

**Q9：一个平台能支撑多少场景？**  
A：知识问答、客服分流、编研生成、API 编排、多租户运营等，**共用同一套资产与引擎**。

**Q10：已有开发团队，二次开发空间如何？**  
A：开放 API 文档齐全；工作流 HTTP 节点可调任意 REST；设计器 SDK 可嵌入定制控制台。
