# 2026-07-02 工作日志

## 知识库切片策略代码评审（只读评审，未改代码）
- 评审范围：`knowledge/chunking/*` 与 `knowledge/service/*` 切片相关实现
- 架构：入口 KnowledgeDocumentSplitter → 解析器层(StructuredDocumentParser) → 策略路由层(DefaultChunkStrategyRouter) → 节点切片层(DefaultNodeChunkStrategy)
- 发现 3 个 P0 严重问题：
  1. token/字符单位混用（结构化路径用 tokenCounter，文本路径用 content.length()，同一 chunkSize 两种语义）
  2. ChunkProfile.defaults() 用 Math.min(500,max) 强压 targetTokens，用户配置的 chunkSize 基本不生效
  3. 结构化路径 splitAtSentenceBoundaries 完全没实现 overlap，overlapTokens 配了不用
- 发现 7 个 P1 中等问题：父 chunk 从未创建(parentId 用 hashCode 且无 PARENT 生成)、createParentChunks/neighborWindow 等配置项是死代码、句子切分正则不覆盖分号且超长句子不二次切、SemanticBoundaryChunker topicShift 只比相邻两句且阈值硬编码、兼容构造函数 new LocalEmbeddingClient 绕过真实 EmbeddingClient、CsvStructureParser 不处理引号转义、OfficeStructureParser 强依赖 Markdown 解析无降级
- 发现 5 个 P2 次要问题：aggregateShortSections 合并跨语义且丢元数据、PlainText sectionPath 空导致永不聚合、KnowledgeSplitter 与 KnowledgeDocumentSplitter 双轨并存、缺切片质量门禁闭环、表格行 rowIndex 与数据行序号不一致
- 评审报告输出：docs/知识库切片策略代码评审报告.md
- 改进建议优先级：先修 P0 三项（单位统一、defaults 尊重配置、overlap 实现）作为切片质量可控基础
